## Project Summary 

With rising digital threats, intrusion detection systems (IDSs) are critical to maintain server security and performance. These systems monitor website traffic to identify and log suspicious activity. Used in tandem with intrusion prevention systems (IPSs), malicious activity can be prevented and blocked. IDSs and IPSs generate massive amounts of data. Using machine learning algorithms, this data can be leveraged to classify cyberattacks from benign site traffic. One type of identified malicious activity includes denial of service (DoS) attacks. DoS attacks aim to interrupt a device’s normal functioning and prevent benign traffic from being processed [1]. This can be accomplished through flood attacks that exhaust server resources (GoldenEye and Hulk) or slow connections that exhaust threads or connections (Slowloris and slowhttptest) [2], [3]. 

If an organization relies on digital infrastructure, being able to identify DoS attacks is crucial as these attacks can create real issues including response delays, financial losses, and service interruptions [4]. These issues cause a severe decrease in the quality of service experienced by users and can have extreme financial consequences. If a business relies on real-time service availability and experiences an attack, they may lose transactions and then also must absorb the cost of mitigating the consequences. Reports have estimated that the direct damages of a DDoS attack, which is a Distributed Denial of Service where several systems are being used to flood the target, can cost a business upwards of $40,000 an hour [5]. In 2016, Dyn, a major domain name system provider, was targeted using DDoS attacks causing widespread outages for several popular websites including Twitter, Netflix, Reddit, Amazon, and Spotify leading to service disruptions for millions of users as well a severe financial repercussions for the websites affected [6], [7]. Disregarding the immediate costs following a DoS attack, these cyberattacks risk alienating system users. Attacks erode trust between users and businesses. Consequentially, cyberattacks also damage businesses’ reputations as well as their network systems. Events like this highlight the importance of IDSs and IPSs for preventing DoS attacks. 

From a technical perspective, DoS detection involves identifying abnormal traffic patterns from legitimate traffic patterns. Traditional detection methods rely on the detection of known signatures and attack patterns but have begun to show limitations as network attacks are becoming more diverse [8]. Modern IDS frameworks have begun to rely more on machine learning techniques to overcome the hurdle of new attack patterns [9]. These models are trained on extensive network traffic data and can then classify incoming data in real-time, allowing for prevention of major attacks. Features can be extracted from flow data and used to characterize behavior by calculating the probability of the traffic being malicious vs benign [9].

However, building these models comes with a set of challenges including imbalanced data, training efficiency, model performance, and scalability to name a few. DoS attacks are much less frequent than benign traffic meaning that many datasets for DoS detection encounters class imbalance, and when selecting the proper dataset to train a model on designers must consider proper sampling techniques to avoid this imbalance. Also, datasets used to train these models can get very large making the use of models computationally expensive, which again must be managed through sampling techniques. Once the models are built, generalization to real data is one of the most important factors to consider as these models need to be accurate and able to detect new unseen attacks. Early identification and response are one of the best ways to manage these attacks before they become catastrophic by allowing companies to deploy mitigation strategies including rate limiting and traffic filtering. However, it is imperative that these models are not overly aggressive, as false positives can negatively affect user experience by interrupting benign traffic. Similarly, making these models scalable and able to handle data in real time given limited resources (bandwidth, storage, and computational power), can be difficult but manageable through limiting the amount of data that needs to be analyzed to detect attacks [9]. 

In this project, we build and present several machine learning classifiers trained to distinguish DoS attacks from benign traffic. To build a machine learning model that can classify attacks, we must use an appropriate dataset to train our model. The dataset used for this project is from the Canadian Institute for Cybersecurity, generated using CICIFlowMeter which is an open-source tool that is an Ethernet traffic Bi-flow generator [10]. The generated dataset contains internet traffic flow data collected over 5 days and includes information such as amount of data transferred (packet size and statistics), packet speed statistics (flow between packets), and counts of flags handling suspicious behavior (for example, RST flag and PSH flag), among others. However, we are only using a one-day subset of the full dataset (Wednesday). We are using this subset as it is the only day that contains both benign and DoS attack traffic to prevent class imbalance. The types of DoS attacks include GoldenEye, Hulk, slowloris, and slowhttptest. It is to be noted that this dataset included instances of Heartbleed traffic, which is when an attacker impersonates the server to gain access to data, but those instances were removed as they are not the same as a DoS attack [11]. Ultimately, using the data associated with these attacks, this project’s goal is to classify DoS attacks. By doing so, threats can be flagged more efficiently, protecting server integrity. 

This work aims to address a technical challenge as well as a business priority. Using machine learning classifiers to detect potentially harmful traffic can reduce financial risk and maintain service availability. As cyber threats continue to evolve, it is important that our defense mechanisms evolve as well. 

## Project Conclusions 

To allow for machine learning classifiers to correctly identify whether traffic was benign or a DOS attack, we first had to make sure the data was cleaned, harmonized, and standardized prior to training the models to give us the best outcomes in performances as possible. In order to do this, we first harmonized the data from three separate file formats, csv, json, and parquet, transforming them into a Pandas data frame for ease of use later in the pipeline. Then we proceeded with cleaning the data, which included: converting all columns to float type to ensure no string types throughout the data frame, dropping duplicate rows and rows that contained NaNs and discarding of any "Heartbleed" type attacks as they were not relevant to the goals of this project. In addition, we created a new Attack_type column where benign was set to 0 and DoS attacks were set to 1, allowing for a target classifier to use later in the pipeline. To continue cleaning the data to better our predictive accuracy, we used univariate analysis to drop columns with low variance, which would add no helpful information to use for our models. 

The data was then split into training and testing sets using a 75/25 split, while the target variable was separated into y_train and y_test. With the data now split, we performed standardization using StandardScaler to normalize feature values, first fitting the scaler on the training data, then applying it to the test dataset. We decided to then proceed with Lasso regression with L1 regularization to remove features that provided no predictive improvements prior to training our classifiers. We removed features with coefficients that were close to zero, which reduced the number of features from 72 to 14. 

After saving the cleaned and reduced feature datasets X_train_selected, X_test_selected, y_train, and y_test to CSV files, we continued in the pipeline with training and testing 5 classifiers: perceptron, logistic regression classifier, adaboost, XGBoost, and lightGBM. We decided to use these 5 classifiers given our discussions in class and the ease of use in implementing them. We hypothesized that XGBoost would perform the best based on our conversations in class and the routine use of this model as a classifier. After creating the classifier models, training them on X_train_selected, and testing them on X_test_selected, models were evaluated using the standard classification tests for performance, accuracy, precision, F1-score, confusion matrix, and AUC. Of the 5 models, XGBoost and LightGBM performed the best, followed closely by the other three models (see metrics above). Interestingly, feature importance was different between XGBoost and LightGBM. XGBoost identified Min_Packet_Length as the highest important feature of the model (72%), followed by Destination_Port (19%). In contrast, LightGBM considered Flow_IAT_Mean to have the highest importance of the model (though with only accounting for 23% of the importance), followed by Init_Win_bytes_backward (16%), Flow_IAT_Max (15%), and Destination Port (10%), a much broader distribution of importance than the XGBoost model.

While an F1 score of 1 when evaluating XGBoost and LightGBM using the test dataset might suggest no further fine-tuning is necessary for these models, if we evaluated independent and external datasets to classify benign vs DoS attacks, we could only assume they would do well. Further testing on changing default arguments within the model training may improve or hinder predictive accuracy, though would be appropriate especially in a context where evaluating metrics would have been poor. We were surprised, but excited, to see all 5 models perform well and learned how beneficial a proper data engineering pipeline can make the machine learning pipeline much more approachable and efficient.
